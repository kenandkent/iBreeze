# iBreeze 部署文档

## 前置工具要求

| 工具 | 版本要求 | 用途 |
|---|---|---|
| Node.js | >= 20 | 前端构建与 lint |
| npm | >= 10 | Node 包管理 |
| Python | >= 3.12 | Backend API / Sidecar |
| uv | >= 0.4 | Python 包管理 |
| Rust | >= 1.75 | Desktop Core |
| cargo-nextest | 最新 | Rust 测试运行器 |
| cargo-llvm-cov | 最新 | Rust 覆盖率 |
| Playwright | 最新 | E2E 测试 |

缺失任一必需工具时 `scripts/verify-all.sh` 直接失败。所有门禁（lint、typecheck、test、coverage、E2E、security audit）失败时总脚本返回非零退出码。

验证内容：
- packages/contracts lint：JSON Schema + Registry 合法性
- Rust desktop-core：fmt、clippy、test (cargo-nextest)、coverage (cargo-llvm-cov, 阈值 100%)、`cargo audit`
- Python backend-api：ruff lint、mypy typecheck、pytest coverage (阈值 100%)
- Python sidecar：ruff lint、mypy typecheck、pytest coverage (阈值 100%)、`pip-audit`
- TypeScript desktop：lint、typecheck、test
- TypeScript admin-web：lint、typecheck、test
- 契约漂移检查：`scripts/check-contract-drift.sh`
- E2E 测试：Playwright
- 安全门禁：Trivy 容器扫描、`cargo deny` license/adv 检查

所有覆盖率阈值固定为 100%，不允许低于此阈值的提交。

## 系统架构

### 远程服务端

| 服务 | 用途 | 端口 |
|---|---|---|---|
| postgres:16 | 数据库 | 51543 |
| minio/minio | S3 对象存储 | 51900 (API) / 51901 (Console) |
| backend-api | FastAPI 后端 | 51080 |
| admin-web | React 管理后台 (Vite) | 51421 (dev) |
| nginx:alpine | API 反向代理 | 51080 → backend-api |

### Desktop 本地组件

| 组件 | 策略 | 说明 |
|---|---|---|
| Rust Trusted Host Kernel | 不可旁路的可信基座 | Duplex UDS Multiplexer、Credential HTTP Broker、CONNECT Egress Proxy、Process Supervisor/Seatbelt |
| Python Sidecar Kernel | 业务域核心 | 11 阶段启动/9 步关闭、Profile 持久化 Kernel（Migrator + WriteQueue + UoW + ReadPool）、Worker Supervisor、Review/Completion State Machine |
| UDS IPC | 认证帧协议 | 4B 长度前缀 + framed JSON-RPC 2.0，Sidecar ↔ Rust Core 间唯一通信通道 |

## 运行时调度与执行

### 计划分发（Dispatcher）

审批通过的计划由 `ibreeze/orchestration/dispatcher.py` 分发为可执行的任务（Task）和运行（Run）。分发流程：

1. 从 `approved` 状态的计划中提取待执行工作项
2. 为每个工作项创建 `company_task` 和 `agent_run` 记录
3. 将 Run 入队至运行时队列（`runtime_queue`），等待调度

### 运行执行器（Run Executor）

`ibreeze/runtime/run_executor.py` 负责处理排队中的 Run：

- 从队列中获取下一项可调度 Run
- 执行租约获取（Lease Acquire）确保并发上限
- 调用对应 Adapter（Codex / Claude Code / OpenCode）执行实际任务
- 执行完成后更新 Run 状态

### 验证循环（Verification Loop）

`ibreeze/runtime/verification_loop.py` 在 Run 执行完毕后运行验证检查：

- 自动运行验证工作流，确认产出符合预期
- 若验证失败，最多执行 **5 轮修复循环**（fix cycles），每轮重新提交修复并再次验证
- 超过修复上限后将 Run 标记为 `failed` 并停止重试

### 相关运行时模块

| 模块 | 职责 |
|---|---|
| `runtime/scheduler.py` | 公平调度、优先级排序、租约管理 |
| `runtime/run_executor.py` | Run 执行入口 |
| `runtime/verification_loop.py` | 验证 + 修复循环 |
| `runtime/checkpoint.py` | 执行快照与断点续跑 |
| `runtime/event_compactor.py` | 事件压缩与日志裁剪 |
| `orchestration/dispatcher.py` | 计划 → Task/Run 分发 |
| `persistence/write_queue.py` | 写入序列化与备份屏障（`barrier()`） |

### 备份与恢复

备份系统使用 **SQLite Online Backup API** 在 WriteQueue 屏障后创建一致性快照，输出为 `tar.zst` 压缩包：

- **命令**：RPC `backup.create` / `backup.restore`
- **格式**：`{backup_id}/backup.tar.zst`（含 `data/profile.db` + CAS 对象 + `manifest.json`）
- **敏感文件排除**：`secrets.json`, `.env`, `credentials.json`, `keys.db`, `id_rsa`, `id_ed25519`
- **外部引用冻结**：备份时自动收集带 FK 约束表的所有行，存入 manifest 的 `external_refs` 字段
- **恢复验证**：还原时执行 `integrity_check`、migration 链完整性、FK 引用完整性
- **保留策略**：支持每日保留（默认 7 天）和每周保留（默认 4 周）
- **一致性保证**：WriteQueue `barrier()` 确保所有待处理写入完成后再进行快照

### 知识库

`ibreeze/knowledge/` 模块管理知识导入、嵌入、检索：

- **SQLite 存储**：`knowledge_items` 表存元数据，`knowledge_fts` 表支持全文检索
- **LanceDB 向量索引**：`knowledge_embeddings` 表，384 维嵌入向量，支持按 `company_id` / `generation_id` 过滤
- **代际追踪**：`embedding_generations` 表记录 `model_key`、`vector_dimension`、`source_event_sequence`
- **一致性检查**：`check_consolidation()` 对比 SQLite 与 LanceDB 计数，暴露代际详情
- **ACL 过滤**：检索前通过 `permitted_knowledge_ids()` 按 `visibility`（company/department/task/private）预授权

- **级别**：默认 `info`，可通过环境变量 `RUST_LOG` 覆盖

# 查看最新日志文件
ls ~/Library/Application\ Support/ibreeze/logs/  # macOS
cat ~/Library/Application\ Support/ibreeze/logs/desktop-core-$(date +%Y-%m-%d).log

# 调整日志级别（开发调试）
RUST_LOG=debug cargo tauri dev

## Recent Changes

### Reverse RPC 自连接防护

`sidecar/ibreeze/runtime/transport.py` 新增 `mark_sidecar_own_socket()` 函数，记录 Sidecar 自身 UDS socket 路径。`ReverseRpcClient._ensure_connected()` 在连接前判断目标 socket 是否为自身路径，若匹配则抛出 `RuntimeError`，防止 Sidecar 误连自身导致死锁。

### Profile 身份验证

`sidecar/ibreeze/application/lifecycle.py` 新增 `_ensure_profile_identity()` 方法，作为 11 阶段启动的 `IDENTITY_VERIFIED` 阶段。启动时验证 `local_profile` 表中的 `backend_origin`、`app_user_id`、`masked_identifier`、`device_id` 字段与构造函数注入值一致，不一致时抛出 `PROFILE_IDENTITY_MISMATCH` 错误。验证通过后更新 `last_opened_at` 时间戳。

### SidecarApplication 启动流程改进

`sidecar/ibreeze/application/app.py` 中 `SidecarApplication` 新增：
- `database_path = profile_root / "profile.db"` 构造，显式管理数据库路径
- `backend_origin`、`app_user_id`、`masked_identifier`、`device_id` 四个身份字段透传给 `ApplicationLifecycle`
- `startup_token`、`app_version`、`launch_id` 传递给 `ProductionRpcServer`

### Handler Registry 遗留跳过前缀

`sidecar/ibreeze/rpc/handler_registry.py` 定义 `_LEGACY_SKIP_PREFIXES`：
- `review.` — 审查相关方法由 `lifecycle.py` 中的 `_init_review_completion_handlers()` 注册的现代 handler 接管
- `completion.` — 完成任务相关方法同样由现代 handler 接管
- `rework.` — 返工处理方法独立注册，不走旧版 `RPCServer.methods`

### Runtime Worker 分发逻辑

`sidecar/ibreeze/workers/runtime.py` 中 `RuntimeWorker` 每隔 25 秒通过 `WriteQueue.submit("runtime.dispatch_ready")` 扫描 `runtime_queue` 中 `status='ready'` 且 `priority >= 10` 的记录，将匹配行标记为 `leased` 状态（每次最多 10 条）。

### Rust reverse.rs Allowlist 更新

`apps/desktop-core/src/rpc/reverse.rs` 更新：
- `ALLOWED_REVERSE_METHODS` 新增 `credential.probe`（含 `profile_directory_id` 参数传递）
- `ALLOWED_REVERSE_NOTIFICATIONS` 新增 `runtime.process.registered`、`runtime.process.exited`
- `handle_credential_probe()` 接受 `profile_directory_id`，从 Keychain 加载凭据后返回 `{"status": "ok"}`

### 契约漂移检查：Sidecar 生成目录

`scripts/check-contract-drift.sh` 新增以下生成目录的比对检查：
- `sidecar/ibreeze/generated/domain_events` — Domain Event 代码生成
- `sidecar/ibreeze/generated/skills` — Skill 代码生成

### Review Repository FOR UPDATE 移除

`sidecar/ibreeze/domain/review/repository.py` 中的 `lock_assignment()` 和 `lock_issue()` 方法移除 `FOR UPDATE` 子句，改用乐观锁（`version` 列）控制并发。`rework_handlers.py` 同样采用乐观锁模式（`UPDATE ... WHERE version=?`），不再使用 `SELECT ... FOR UPDATE`。
