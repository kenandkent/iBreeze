# iBreeze 部署文档

## 前置工具要求

| 工具 | 版本要求 | 用途 |
|---|---|---|
| Node.js | >= 20 | 前端构建与 lint |
| npm | >= 10 | Node 包管理 |
| Python | >= 3.12 | Backend API / Sidecar |
| uv | >= 0.4 | Python 包管理 |
| Rust | >= 1.75 | Desktop Core |
| cargo-nextest | 最新 | Rust 测试运行器 |
| cargo-llvm-cov | 最新 | Rust 覆盖率 |
| Playwright | 最新 | E2E 测试 |

缺失任一必需工具时 `scripts/verify-all.sh` 直接失败。所有门禁（lint、typecheck、test、coverage、E2E）失败时总脚本返回非零退出码。

## 系统架构

| 服务 | 用途 | 端口 |
|---|---|---|
| postgres:16 | 数据库 | 51543 |
| minio/minio | S3 对象存储 | 51900 (API) / 51901 (Console) |
| backend-api | FastAPI 后端 | 51080 |
| admin-web | React 管理后台 (Vite) | 51421 (dev) |

## 一键部署（推荐）

### 后台服务

```bash
# 1. 构建并启动所有服务
docker compose up -d

# 2. 创建 MinIO 存储桶
docker exec ibreeze-minio-1 mc alias set local http://localhost:9000 minioadmin minioadmin
docker exec ibreeze-minio-1 mc mb local/ibreeze

# 3. 运行数据库迁移
cd apps/backend-api
IBREEZE_DATABASE_URL="postgresql+asyncpg://ibreeze:ibreeze_password@localhost:51543/ibreeze" \
  uv run alembic upgrade head

# 4. 验证服务健康
curl http://localhost:51080/health
# 预期: {"status":"ok"}

# 查看实时日志
docker compose logs -f
```

### 管理后台前端

```bash
cd apps/admin-web
npm install
npm run dev
# 访问 http://localhost:51421
```

## 本地分步启动

### 数据库和存储

```bash
# PostgreSQL
docker run -d --name ibreeze-postgres \
  -e POSTGRES_DB=ibreeze \
  -e POSTGRES_USER=ibreeze \
  -e POSTGRES_PASSWORD=ibreeze_password \
  -p 51543:5432 \
  postgres:16

# MinIO
docker run -d --name ibreeze-minio \
  -e MINIO_ROOT_USER=minioadmin \
  -e MINIO_ROOT_PASSWORD=minioadmin \
  -p 51900:9000 \
  -p 51901:9001 \
  minio/minio server /data --console-address ":51901"

# 创建 MinIO 存储桶
docker exec ibreeze-minio-1 mc alias set local http://localhost:9000 minioadmin minioadmin
docker exec ibreeze-minio-1 mc mb local/ibreeze
```

### 后端 API (开发模式)

```bash
cd apps/backend-api
uv sync
IBREEZE_DATABASE_URL="postgresql+asyncpg://ibreeze:ibreeze_password@localhost:51543/ibreeze" \
  uv run alembic upgrade head
IBREEZE_DATABASE_URL="postgresql+asyncpg://ibreeze:ibreeze_password@localhost:51543/ibreeze" \
  uv run uvicorn ibreeze_backend.main:app --reload --host 0.0.0.0 --port 51080
```

### 管理后台 UI (开发模式)

```bash
cd apps/admin-web
npm install
npm run dev
```

### 桌面客户端

```bash

cd apps/desktop

bash scripts/build-desktop.sh

```

## 运行时调度与执行

### 计划分发（Dispatcher）

审批通过的计划由 `ibreeze/orchestration/dispatcher.py` 分发为可执行的任务（Task）和运行（Run）。分发流程：

1. 从 `approved` 状态的计划中提取待执行工作项
2. 为每个工作项创建 `company_task` 和 `agent_run` 记录
3. 将 Run 入队至运行时队列（`runtime_queue`），等待调度

### 运行执行器（Run Executor）

`ibreeze/runtime/run_executor.py` 负责处理排队中的 Run：

- 从队列中获取下一项可调度 Run
- 执行租约获取（Lease Acquire）确保并发上限
- 调用对应 Adapter（Codex / Claude Code / OpenCode）执行实际任务
- 执行完成后更新 Run 状态

### 验证循环（Verification Loop）

`ibreeze/runtime/verification_loop.py` 在 Run 执行完毕后运行验证检查：

- 自动运行验证工作流，确认产出符合预期
- 若验证失败，最多执行 **5 轮修复循环**（fix cycles），每轮重新提交修复并再次验证
- 超过修复上限后将 Run 标记为 `failed` 并停止重试

### 相关运行时模块

| 模块 | 职责 |
|---|---|
| `runtime/scheduler.py` | 公平调度、优先级排序、租约管理 |
| `runtime/run_executor.py` | Run 执行入口 |
| `runtime/verification_loop.py` | 验证 + 修复循环 |
| `runtime/checkpoint.py` | 执行快照与断点续跑 |
| `runtime/event_compactor.py` | 事件压缩与日志裁剪 |
| `orchestration/dispatcher.py` | 计划 → Task/Run 分发 |

## 常见运维

### 查看日志

```bash
docker compose logs -f backend-api   # 仅后端
docker compose logs -f postgres      # 仅数据库
docker compose logs -f minio         # 仅对象存储
```

### 桌面客户端日志

桌面客户端 Rust Core 使用 `tracing` 输出日志：

- **控制台**：stderr 实时输出（开发模式）
- **文件**：`$LOCAL_APP_DATA/ibreeze/logs/desktop-core-{YYYY-MM-DD}.log`（每日轮转，保留 30 天）
- **格式**：JSON（文件）/ ANSI 彩色（控制台）
- **级别**：默认 `info`，可通过环境变量 `RUST_LOG` 覆盖

```bash
# 查看最新日志文件
ls ~/Library/Application\ Support/ibreeze/logs/  # macOS
cat ~/Library/Application\ Support/ibreeze/logs/desktop-core-$(date +%Y-%m-%d).log

# 调整日志级别（开发调试）
RUST_LOG=debug cargo tauri dev
```

### 停止/重启

```bash
docker compose down        # 停止所有服务
docker compose up -d       # 重新启动
docker compose restart     # 重启
```

### 完全重置（清除数据）

```bash
docker compose down -v     # 停止并删除卷（数据会丢失）
docker compose up -d       # 重新创建
# 之后重新创建 MinIO 存储桶和运行迁移
```

### 从零重新部署

```bash
# 卸载旧版
docker compose down -v
docker system prune -a --volumes -f

# 清理本地缓存
rm -rf apps/backend-api/.venv sidecar/.venv apps/admin-web/node_modules apps/desktop/node_modules
pip cache purge
uv cache clean
npm cache clean --force

# 重新安装
cd apps/backend-api && uv sync
cd ../admin-web && npm install

# 构建 Docker 镜像
cd ../..
docker compose build
docker compose up -d
# 然后创建存储桶 + 迁移数据库
```

## 环境变量

### 后台 API

| 变量 | 说明 | 默认值 |
|---|---|---|
| IBREEZE_DATABASE_URL | PostgreSQL 连接串 | `postgresql+asyncpg://ibreeze:ibreeze@localhost:51543/ibreeze` |
| IBREEZE_API_PORT | 后端 API 监听端口 | `51080` |
| IBREEZE_S3_ENDPOINT_URL | MinIO/S3 端点 | `http://localhost:51900` |
| IBREEZE_S3_ACCESS_KEY_ID | S3 访问密钥 | `minioadmin` |
| IBREEZE_S3_SECRET_ACCESS_KEY | S3 密钥 | `minioadmin` |
| IBREEZE_S3_BUCKET_NAME | S3 存储桶名 | `ibreeze` |
| IBREEZE_JWT_SECRET | JWT 签名密钥 | - |
| IBREEZE_CATALOG_SIGNING_KEY | 目录签名私钥 | - |

### 桌面客户端

桌面客户端通过 Tauri 配置文件设置，不使用环境变量。

| 变量 | 说明 | 默认值 |
|---|---|---|
| RUST_LOG | Rust Core 日志级别过滤 | `info` |
